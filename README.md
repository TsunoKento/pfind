# 並列ファイル検索CLI

ディレクトリ配下のファイルを **並列に走査**し、ファイル名/内容を検索して一致箇所を出力するCLIツール。

> 目的：`grep` / `find` 的な「探す」を、並列化で高速に、かつ最低限の分かりやすいI/Fで提供する

---

## 1. 用語

- **ルートパス**: 検索を開始するディレクトリ（複数指定可）
- **対象ファイル**: 検索処理の入力となるファイル
- **マッチ**: 検索条件に一致した結果（ファイル名一致/内容一致）

---

## 2. ゴール / 非ゴール

### ゴール（このツールで必ずやる）
- ルートパス配下を再帰走査し、対象ファイルを列挙できる
- 並列ワーカーでファイル検索を行い、結果を標準出力へストリーム出力できる
- Ctrl-C 等で安全に中断できる
- 代表的な検索ニーズ（内容検索・ファイル名検索・拡張子フィルタ・除外）がCLIオプションで指定できる

### 非ゴール（今回やらない / 後回し）
- ripgrep級のフル互換（高度な正規表現最適化、色付け、巨大機能セット）
- `.gitignore` 等の完全互換解釈（必要なら将来 `--gitignore` として追加）
- PDF/Officeなどバイナリ文書の中身解析（対象外、スキップ）

---

## 3. 対応環境
- macOS / Linux / Windows（パス区切りなどはOS依存を吸収）
- 標準入力は必須ではない（将来拡張余地は残す）
- 実装言語: Go 1.21以上（`runtime.NumCPU()` でワーカーデフォルト数を取得）

---

## 4. 使い方（CLI I/F）

### コマンド（仮名）
- コマンド名: `pfind`

### 基本形
- **内容検索**（デフォルト）
  - `pfind [options] <pattern> [path ...]`
- **ファイル名検索**
  - `pfind --name <pattern> [path ...]`

### 引数
- `<pattern>`: 検索パターン（デフォルトは「固定文字列」検索）
- `[path ...]`: 検索ルート（省略時は `.`）

---

## 5. オプション仕様

### 検索モード
- `--name`
  ファイル名（ベース名）を検索対象にする（内容検索ではなくなる）
- `--content`（将来用 / 明示）
  内容検索を明示（デフォルトなので省略可）

### パターン解釈
- `-F, --fixed`（デフォルト）
  固定文字列として検索
- `-E, --regex`
  正規表現として検索（RE2相当など実装言語の標準に準拠）
- `-i, --ignore-case`
  大文字小文字を無視

### 走査範囲
- `-r, --recursive`（デフォルトON）
  再帰走査
- `--max-depth <n>`（デフォルト: 無制限）
  深さ制限（0=指定したディレクトリ直下のみ）
- `--hidden`（デフォルトOFF）
  ドットで始まる隠しファイル/ディレクトリを含める
- `--follow-symlinks`（デフォルトOFF）
  シンボリックリンクを辿る（循環対策が必要）

### 対象フィルタ
- `--include <glob>`（複数可）
  例: `--include "*.go" --include "*.md"`
- `--exclude <glob>`（複数可）
  例: `--exclude "node_modules/**" --exclude ".git/**"`
- `--type <f|d>`（デフォルト: f）
  `f`: ファイルのみ、`d`: ディレクトリ名検索（※ `--name` と組み合わせ前提）
  `--name` なしで `--type d` を指定した場合は終了コード2のエラー

### 並列度/性能
- `-j, --workers <n>`（デフォルト: 論理コア数（`runtime.NumCPU()`））
  ワーカー数
- `--max-bytes <n>`（デフォルト: 10MiB（= 10 × 1,048,576 バイト））
  これを超えるファイルはスキップ（内容検索時）
- `--binary {skip|search}`（デフォルト: skip）
  バイナリ判定（NUL含む等）したファイルをどう扱うか

### 出力
- `-n, --line-number`（デフォルトON）
  行番号を出す
- `--column`（デフォルトOFF）
  列番号も出す（固定文字列なら先頭位置、正規表現なら最初のmatch開始）
- `-c, --count`
  マッチ数のみ出力（ファイルごと）
- `-l, --files-with-matches`
  マッチしたファイルのパスのみ出力（行番号・テキスト不要。内容検索時のみ有効）
- `--json`
  JSON Lines形式で出力（機械処理向け）
- `--sort`（デフォルトOFF）
  出力順を安定化（パス→行番号でソート）。※メモリ消費増

### その他
- `-V, --version`
  バージョン番号を表示して終了

### 終了コード
- `0`: マッチあり
- `1`: マッチなし
- `2`: エラー（致命的：不正引数、内部エラーなど）
- `130`: 中断（SIGINT相当）

---

## 6. 出力仕様

### 標準（テキスト）出力（デフォルト）
内容検索:
- `path:line:text`
- `--column` 指定時: `path:line:col:text`

ファイル名検索（--name）:
- `path`（マッチしたパスのみ列挙）
- `--count` はファイル名検索では意味をなさないため未対応。`--name` と `--count` を同時に指定した場合は終了コード2のエラー

ファイルパス一覧（-l / --files-with-matches）:
- `path`（内容検索でマッチしたファイルのパスのみ）

### JSON Lines（--json）
1行＝1レコードのJSON。
例（内容検索）:
```json
{"path":"./a/b.txt","line":12,"column":5,"text":"...原文...","match":"pattern"}
```

---

## 7. 並列処理モデル（設計要件）

### スレッド/ゴルーチンモデル（例）

- **Walker**: ディレクトリを走査して「対象ファイルパス」をキューへ投入
- **Workers**: キューからファイルを受け取り、検索して結果を `results` へ送る
- **Printer/Aggregator**: `results` を受けて標準出力へ出す
- `--sort` 有効時は Aggregator が全件バッファし、ソート後に出力

### キャンセル

- Ctrl-C でキャンセル（context cancel / signal）
- キャンセル後は可能な範囲で早期終了し、未処理タスクを捨てる
- 出力は「途中まで出る」ことを許容（中断は正常系）

### バックプレッシャ

- ファイルキューは有限バッファ（例: 1k件）を持ち、Walkerが暴走しないようにする
- 同時オープン数の増えすぎを防ぐ（Worker数が上限）

---

## 8. 例

内容検索（固定文字列）:
```
pfind "TODO" .
```

正規表現で検索:
```
pfind -E "func\s+\w+\(" --include "*.go" .
```

除外しつつ並列度を上げる:
```
pfind "password" --exclude "node_modules/**" --exclude ".git/**" -j 8 .
```

ファイル名検索:
```
pfind --name "README" .
```

JSON出力（他ツール連携）:
```
pfind "panic" --json . | jq -r '.path'
```

---

## 9. エラーハンドリング方針

- 権限エラー等で「読めないファイル」があっても全体は継続（警告は stderr へ）
- 不正な引数や初期化失敗など、回復不能は即終了コード2
- `--max-bytes` 超過・バイナリスキップは stderr に出さない（うるさくなるため）。必要なら `--verbose` を将来追加

---

## 10. パフォーマンス要件（目安）

- 10k〜100kファイル規模で破綻しない（メモリが線形に増えない設計）
- デフォルトは「結果をストリーム出力」して、全件保持しない（`--sort` を除く）

---

## 11. テスト方針

### ユニットテスト

- パターンマッチ（fixed/regex, ignore-case）
- include/exclude glob
- バイナリ判定、max-bytes判定

### 結合テスト

- 一時ディレクトリにfixtureを作って実行→出力検証
- 競合検証（`go test -race`）
- Windowsパス/改行コード差異も考慮（テストでは正規化）

---

## 12. 開発メモ（実装者向け）

- 出力順はデフォルト非決定的（並列なので）。安定が必要なら `--sort`
- 大きいファイルは行単位ストリーム処理（丸読みしない）
- `--follow-symlinks` は循環検出（訪問済みinode/realpath）を必須要件にする
- ビルド: `go build -trimpath`
- Goバージョン: 1.21以上必須（`slices`, `maps` パッケージ等）
